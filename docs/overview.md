# Назначение, аудитория, сценарии и границы решения

Документ для п. 6.1 ТЗ.

## Назначение

РобоПодбор — веб-платформа экспресс-оценки роботизации объекта до дорогой предварительной
проработки. За один сеанс пользователь выбирает объект и задаёт его параметры, получает подбор
роботов с причинами, экономику трёх сценариев (текущее состояние, покупка, роботы как услуга —
RaaS), проверку расчёта на 2D-модели и отчёт. Результат — предварительная оценка, а не
инвестиционное решение: она требует верификации при обследовании объекта.

## Целевая аудитория

| Кто | Что получает |
|---|---|
| Руководители предприятий и подразделений | Окупится ли роботизация и за какой срок |
| Технические директора | Применимы ли решения к объекту и его инфраструктуре |
| Руководители по автоматизации и цифровой трансформации | Сравнение альтернатив по единым показателям |
| Логисты | Сколько роботов нужно и справится ли парк с пиком |
| Операционные и финансовые аналитики, специалисты по предварительному обоснованию | CAPEX, OPEX, ROI, формулы и допущения; материалы для ТЭО и пилота |

Интерфейс на русском языке, для пользователей без навыков программирования (п. 4.5 ТЗ).

## Пользовательские сценарии

**Путь из 8 шагов** (п. 2.2 ТЗ): 1 Объект → 2 Параметры → 3 Подбор → 4 Сравнение →
5 Экономика → 6 What-if → 7 Симуляция → 8 Экспорт. Подробно — `docs/user-guide.md`.

| Роль | Сценарий |
|---|---|
| Гость | Каталог роботов и сравнение; весь путь из 8 шагов на `/demo` без регистрации. Расчёт не сохраняется, ввод хранится только во вкладке браузера |
| Пользователь | Регистрация и вход; проекты (создать, изменить, копировать, удалить); путь из 8 шагов с сохранением; история расчётов с версиями модели и данных; отчёт для печати и PDF, выгрузка Excel и CSV |
| Администратор | Всё, что доступно пользователю, и управление каталогом роботов: добавить, изменить, удалить (`docs/admin-guide.md`) |

Типы объектов: склад, аэропорт, больница — отдельные наборы параметров, подбор и экономика
для каждого; 2D-симуляция — для склада.

## Границы решения

Входит:

- подбор по жёстким ограничениям (грузоподъёмность, ширина прохода, производительность) и
  объяснимый балл (`docs/recommendation.md`);
- экономика трёх сценариев по 8 показателям с формулами и источниками, чувствительность,
  what-if (`docs/economics.md`);
- 2D-проверка, справится ли расчётный парк с пиковым часом (`docs/simulation.md`);
- хранение проектов и истории расчётов на сервере, роли и изоляция данных.

Не входит (подробно — `docs/limitations.md`):

- данные организатора: каталог демонстрационный, импорта каталога и API импорта нет;
- серверный PDF: PDF формируется печатью отчёта из браузера;
- интеграции с WMS, ERP/1С и системами мониторинга — только описаны (`docs/architecture.md`);
- амортизация, заёмное финансирование, замена компонентов в ТСО;
- 2D-планы аэропорта и больницы.
