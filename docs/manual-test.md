## 1. Подготовка

### 1.1. Запуск

- [ ] `cd frontend && npm ci`
- [ ] `npm run type-check` — завершается без ошибок.
- [ ] `npx vitest run` — все тесты зелёные (ожидается 269).
- [ ] `npm run build` — сборка проходит (предупреждение о размере чанка — не ошибка).
- [ ] `npm run dev` → открыть адрес из консоли Vite (обычно `http://localhost:5173`).
  Либо Docker-сборка: `docker compose up -d --build` → `http://localhost:8080` (`docs/deployment.md`).

Важно:

- Проверять только в режиме моков: `npm run dev` (`frontend/.env.development`) или Docker-сборка
  с `VITE_USE_MOCKS=true`. Бэкенд — каркас (`docs/api.md`): с `VITE_USE_MOCKS=false` экраны с
  данными не работают.
- **Данные моков сохраняются в `localStorage`** (ключ `robo.mockDb`) после каждого изменения:
  проекты, расчёты, каталог и зарегистрированные пользователи переживают F5. Вернуть исходное
  состояние — «Сбросить демо-данные» в `/admin/robots` (раздел 4) или
  `localStorage.removeItem('robo.mockDb')` в консоли и F5.
- **Черновик мастера** (шаг, ввод, выбор роботов, сценарии) хранится в `sessionStorage` вкладки:
  F5 возвращает на тот же шаг, закрытие вкладки — очищает.
- Перед проверкой начните с чистого состояния: «Сбросить демо-данные» или новая вкладка в режиме
  инкогнито.

### 1.3. Имитация недоступного сервера (mockOffline)

Консоль DevTools (F12 → Console):

- Включить: `localStorage.setItem('mockOffline', '1')`
- Выключить: `localStorage.removeItem('mockOffline')`

Перезагрузка не нужна: ключ читается при каждом запросе. Но типы объектов и список роботов
мастер кэширует на всю сессию — чтобы увидеть ошибку на шаге «Объект», включите ключ и нажмите F5.

Ожидаемый вид ошибки везде, где есть блок ошибки: заголовок «Нет связи с сервером», текст «Сервер
недоступен. Проверьте подключение к сети и повторите попытку», кнопка «Повторить».

### 1.4. Окно 1366×768

- Chrome/Edge: F12 → Ctrl+Shift+M (Toggle device toolbar) → в списке устройств «Responsive» →
  ширина `1366`, высота `768`, масштаб 100 %.
- Проверка отсутствия горизонтальной прокрутки страницы — в консоли:
  `document.documentElement.scrollWidth <= document.documentElement.clientWidth` → `true`.
- Широкие таблицы (каталог, сравнение, допущения, состав оборудования, таблицы графиков, отчёт)
  должны прокручиваться внутри своего блока, а не всей страницей.

## 6. Проверка ошибок и краевых случаев

### 6.1. Вход и регистрация

- [ ] Неверный пароль: `/login`, `user@demo.ru` / `wrong123` → блок «Неверная почта или пароль» с
  текстом «Неверная почта или пароль. Проверьте раскладку и Caps Lock»; остаёмся на форме.
- [ ] Неверный формат почты: `user@` → после ухода с поля «Введите почту в формате name@company.ru».
- [ ] Занятая почта: `/register`, имя «Тест», `user@demo.ru`, пароль `Password1` → «Такие данные уже
  существуют» / «Пользователь с такой почтой уже зарегистрирован — войдите или укажите другую почту».
- [ ] Короткий пароль: `/register`, пароль `1234567` → под полем «Пароль должен быть не короче 8
  символов», запрос не отправляется. (Ответ сервера 400 VALIDATION_ERROR из интерфейса не достичь —
  клиентская проверка срабатывает раньше.)
- [ ] Успешная регистрация `new@test.ru` / `Password1` → вход, переход на `/app/projects` (или на
  адрес из `redirect`), пустой список «Создайте первый проект». F5 → пользователь остаётся в системе.
- [ ] Недействительный токен (401 AUTH_REQUIRED): войдя как пользователь, в консоли
  `localStorage.setItem('auth.token', 'mock-token:bad')`, F5, открыть `/app/projects` → выход из
  системы и переход на `/login?redirect=/app/projects`. То же для пользователя `new@test.ru` после
  «Сбросить демо-данные» (его учётка удалена).

### 6.2. Доступ

- [ ] Чужой проект: войти `admin@demo.ru`, открыть `/app/projects/c2d4e6f8-2222-4b02-9d02-000000000001`
  (проект пользователя «Подольск») → «Проект не найден» (моки отвечают 404, а не 403). Отчёт
  `/app/projects/c2d4e6f8-2222-4b02-9d02-000000000001/report` → блок ошибки «Проект не найден —
  возможно, он был удалён» с «Повторить».
- [ ] Несуществующий проект: `/app/projects/xxx` → «Проект не найден».
- [ ] Несуществующий робот: `/catalog/xxx` → заголовок «Карточка робота», блок «Данные не найдены» /
  «Робот не найден — возможно, он был удалён», кнопка «Повторить».
- [ ] Несуществующий адрес: `/abc` → «Страница не найдена» / «По этому адресу ничего нет», кнопки
  «На главную», «Каталог роботов».
- [ ] Защищённый адрес без входа: `/app/projects/<id>` → вход → возврат на этот проект.
- [ ] 403 FORBIDDEN (POST /robots не админом) в интерфейсе недостижим: пункт меню скрыт, маршрут
  закрыт (раздел 4, п. 19).

### 6.3. Каталог

- [ ] Пустой результат по поиску: `/catalog`, «Поиск» → `zzz` → «Найдено: 0», «Роботы не найдены»,
  «По выбранным фильтрам в каталоге ничего нет…», «Сбросить фильтры» → «Найдено: 10».
- [ ] Пустой результат по фильтрам: «Тип объекта» Больница + «Тип решения» «Автоматизированная
  система хранения» → то же пустое состояние. Фильтры сохраняются в адресе: F5 — те же фильтры.
- [ ] Сравнение: отметить 2 робота → «Сравнить (2)» → диалог сравнения; 4-го выбрать нельзя.

### 6.4. mockOffline на каждом экране с запросом

Включить ключ (раздел 1.3). После каждого пункта — выключить и проверить «Повторить».

- [ ] `/` — F5 → блок ошибки вместо карточек типов объектов.
- [ ] `/login` — «Войти» → блок «Нет связи с сервером».
- [ ] `/register` — «Зарегистрироваться» → тот же блок.
- [ ] `/catalog` — сменить фильтр → блок ошибки вместо таблицы, «Повторить» после выключения —

## 7. Известные недоделки

Функции, которые не реализованы или реализованы частично, и причины — в **`docs/limitations.md`**
(главный документ для п. 5.7 ТЗ). Ключевое оттуда, что видно при ручной проверке:

- демо работает на мок-сервере в браузере, данные хранятся в `localStorage`; бэкенд — каркас,
  серверное ядро расчёта — заглушка (`docs/api.md`);
- каталог роботов вымышленный, датасеты организатора не загружены;
- «Скачать Excel» неактивна (формирует сервер), импорта каталога нет;
- симуляция только для склада, порог подтверждения 90 %;
- амортизации нет, ТСО без замены компонентов;
- новые поля аэропорта и больницы в подборе не участвуют;
- допущения проекта меняются только на шаге What-if и в проект не сохраняются;
- сценарии, процессы и выбор роботов хранятся в черновике вкладки и в сохранённых расчётах, а не в
  проекте.

Ниже — недоделки интерфейса, которых нет в `docs/limitations.md`. Критичность — для демонстрации
жюри: **высокая** — видно на основном пути; **средняя** — видно при внимательной проверке;
