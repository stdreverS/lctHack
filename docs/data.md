# Данные: каталог, справочники, версии

Документ для п. 6.6 ТЗ: структура данных, откуда они взяты, как обновляются, как версионируются.

## Где лежат данные

**Сервер** (основная конфигурация):

| Данные | Где | Кто использует |
|---|---|---|
| Каталог роботов | PostgreSQL, таблица `robots`; начальные 10 записей — `backend/seed/robots.json` | `Robo.Api` (`/robots`), расчётное ядро |
| Пользователи | PostgreSQL, `users`; демо-учётки — `backend/seed/users.json` (пароли — хэши BCrypt) | авторизация |
| Проекты и история расчётов | PostgreSQL, `projects`, `calculations` (запрос и результат — jsonb) | `Robo.Api` |
| Типы объектов: поля форм, группы, процессы, демо-параметры, план для симуляции | `backend/config/object-types.json` | `ConfigLoader` → `GET /object-types`, ядро |
| Нормативы и коэффициенты модели с источниками (24 записи) | `backend/config/norms.json` | `ConfigLoader` → ядро `econ-1.0+rec-1.0` |

Начальные данные заливаются при первом запуске API в пустые таблицы (`SeedRunner`).

**Браузер:**

| Данные | Где | Кто использует |
|---|---|---|
| Черновик мастера (шаг, ввод, выбор роботов) | `sessionStorage` вкладки, ключи `robo.wizard.*` | `frontend/src/stores/wizardDraft.ts` |
| Токен и пользователь | `localStorage` | `frontend/src/stores/auth.ts` |

**Автономное демо на моках** (`VITE_USE_MOCKS=true`, без сервера): те же данные в копиях
`frontend/src/mocks/data/*.ts` (каталог, типы объектов, демо-пользователи и демо-проекты,
коэффициенты `MOCK_CONST`), изменения — в `localStorage`, ключ `robo.mockDb`. Совпадение копий
проверяют тесты: `objectTypes.test.ts` — с `object-types.json`, эталонные расчёты
(`golden.test.ts` и `GoldenCalculationTests.cs`) — модель и коэффициенты.

## Структура каталога

Робот (`Robot` в `frontend/src/types/api.ts`, раздел 5 CLAUDE.md):

| Группа (п. 3.3.7 ТЗ) | Поля |
|---|---|
| Идентификация | `name`, `manufacturer`, `solutionType` (код, например `amr`), `solutionTypeName`, `country` |
| Технические характеристики (`specs`) | `payloadKg`, `speedMps`, `perfOpsPerHour`, `autonomyH`, `chargeTimeH`, `positioningMm`, `navigation` |
| Инфраструктура (`specs`) | `minAisleM`, `widthM`, `lengthM`, `heightM` |
| Экономика | `price` (₽ с НДС), `raasMonthlyPrice` (₽/мес, `null` — аренды нет), `maintenancePerYear` (₽/год), `specs.lifeYears` |
| Применимость | `objectTypes` (коды типов объектов), `availability` |
| Качество данных | `sourceUrl`, `sourceDate`, `confirmed` |

Любая характеристика может быть `null` — в интерфейсе «нет данных», в подборе такая проверка
получает результат «нет данных», а робот — статус «Требует проверки», если проверка критичная.

Иерархия каталога: тип объекта (`objectTypes`) → тип решения (`solutionType`) → продукт.
Процессы объекта в модели робота не хранятся.

## Типы объектов

Тип объекта (`ObjectType`): код, название, описание, процессы, группы полей, поля (`ParamField`:
тип, единица, диапазон, обязательность, значение по умолчанию, пример, подсказка, источник
норматива), демо-параметры и план для симуляции (`layout`, у аэропорта и больницы — `null`).

| Тип | Полей | Процессов | План |
|---|---|---|---|
| Склад (`warehouse`) | 16 | 5 | есть |
| Аэропорт (`airport`) | 17 | 3 | нет |
| Больница (`hospital`) | 14 | 3 | нет |

Формы параметров строятся по описанию полей, поэтому новый тип объекта или поле добавляется
правкой данных, без изменения кода экранов.

## Откуда данные

- **Каталог роботов — вымышленный.** Производители и характеристики условные, ссылки ведут на
  `example.com`. Каталог организатора (PDF, `catalog_export_v5`) в проект не загружен.
- **Демо-параметры объектов** придуманы командой как правдоподобные; обезличенные примеры
  организатора (п. 7.2 ТЗ) не загружены.
- **Нормативы:** ТК РФ ст. 91 (длительность смены), ГОСТ 33757-2016 (размеры поддона
  1200×800), СП 158.13330.2014 (ширина коридоров больницы) — указаны как источники значений по
  умолчанию. В `norms.json` подтверждены 3 записи из 24, остальные — демо-оценки команды
  (`confirmed: false`).

## Как обновлять

| Что | Как |
|---|---|
| Робот | Администратор: `/admin/robots` → «Добавить робота» / «Изменить» / «Удалить» (`docs/admin-guide.md`) или API `POST/PUT/DELETE /robots`; изменения сразу сохраняются в БД |
| Исходный каталог | Правка `backend/seed/robots.json`; применяется к пустой базе (новое развёртывание или `docker compose down -v`). Для автономного демо — и `frontend/src/mocks/data/robots.ts` |
| Тип объекта или поле | Правка `backend/config/object-types.json` и копии `frontend/src/mocks/data/objectTypes.ts`; тест проверяет совпадение. В Docker папка `config` смонтирована — достаточно `docker compose restart api` |
| Нормативы и коэффициенты | Правка `backend/config/norms.json` (и `MOCK_CONST` для автономного демо); расхождение ловят эталонные тесты |
| Вернуть исходные данные | Сервер: пересоздать базу (`docker compose down -v` и `up`). Автономное демо: `/admin/robots` → «Сбросить демо-данные» |
| Параметры объекта пользователя | Ручной ввод или CSV по шаблону на шаге «Параметры» (`docs/user-guide.md`) |

Импорта каталога из файла и автоматического обновления нет.

## Версии

| Версия | Значение | Где задаётся | Где видна |
|---|---|---|---|
| Данные (`dataVersion`) | `catalog-2026.09` | `dataVersion` в `norms.json` (в автономном демо — `DATA_VERSION` в `mocks/data/calculation.ts`) | в каждом расчёте, истории, отчёте |
| Модель (`modelVersion`) | `econ-1.0+rec-1.0` (сервер), `mock-1.0` (автономное демо, те же формулы) | `CalculationEngine.ModelVersion`; `MODEL_VERSION` в моках | там же |
| Движок симуляции | `sim-1.2` | `SIM_MODEL.engineVersion` | KPI симуляции, отчёт |

Каждый расчёт хранит запрос и результат с версиями, поэтому сохранённый расчёт открывается
в том виде, в каком был посчитан (п. 3.1.5).

## Ограничения

- Каталог и демо-параметры вымышленные; данные организатора не загружены.
- Версия данных — константа: правка каталога в админке её не меняет.
- В автономном демо данные хранятся в браузере: у каждого браузера свои.
- Источник, дата и подтверждённость хранятся для робота целиком, а не для каждой характеристики.
- Нормативы заданы дважды (`norms.json` и `MOCK_CONST` для автономного демо); синхронность
  проверяют эталонные тесты на пяти расчётах, а не общий код.
- Импорта каталога и API импорта данных (п. 3.3.2, 3.8.2) нет.
