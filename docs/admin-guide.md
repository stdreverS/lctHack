# Руководство администратора

Для п. 6.7 ТЗ. Администратор управляет каталогом роботов. Всё, что доступно пользователю
(`docs/user-guide.md`), доступно и администратору; к чужим проектам доступа нет.

## Вход

`/login` → `admin@demo.ru` / `Admin12345` → «Войти». В шапке появится ссылка
«Администрирование» (`/admin/robots`). Пользователь без роли администратора туда не попадёт:
платформа покажет «Недостаточно прав» и вернёт к проектам.

## Каталог роботов (`/admin/robots`)

Таблица всех роботов: название, производитель, тип решения, типы объектов, ключевые
характеристики, действия. Поиск — по названию, производителю или типу решения; рядом —
«Показано: N из M» и ссылка «Открыть публичный каталог». Таблица прокручивается внутри себя,
столбцы «Название» и «Действия» закреплены.

### Добавить робота

1. «Добавить робота» — справа откроется форма.
2. Заполните группы полей:

   | Группа | Поля (* — обязательные) |
   |---|---|
   | Идентификация | Название*, Производитель*, Тип решения* (выбор или новый код латиницей, например `amr`), Название типа решения*, Страна производства |
   | Технические характеристики | Грузоподъёмность, Скорость, Производительность (опер./ч — основа расчёта числа роботов), Автономность, Время зарядки, Точность позиционирования, Навигация |
   | Требования к инфраструктуре | Минимальная ширина прохода (проверяется при подборе), Ширина, Длина, Высота |
   | Экономика | Цена покупки* (₽ с НДС за робота), Аренда (RaaS) в месяц (пусто — аренда не предлагается), Обслуживание в год*, Срок службы |
   | Применимость | Типы объектов* (где робот участвует в подборе), Доступность поставки |
   | Качество данных | Источник (ссылка), Дата данных, «Данные подтверждены источником» |

3. «Добавить робота». Робот сразу появляется в публичном каталоге и в подборе.

Пустая характеристика показывается как «нет данных»; если она нужна для критичной проверки
(грузоподъёмность, ширина прохода, производительность), робот получит статус «Требует
проверки». Без отметки «Данные подтверждены» характеристики показываются как допущение и
снижают балл робота (`docs/recommendation.md`).

### Изменить робота

Кнопка редактирования в строке → та же форма с текущими значениями → «Сохранить изменения».
Уже сохранённые расчёты проектов не меняются: в них хранится результат на момент расчёта.

### Удалить робота

Кнопка удаления в строке → подтверждение «Удалить робота?» → «Удалить». Робот исчезает из
каталога и подбора; сохранённые расчёты не меняются. Действие нельзя отменить.

### Сбросить демо-данные

Кнопка «Сбросить демо-данные» есть только в автономном демо на моках → подтверждение → «Сбросить».
Проекты, расчёты, изменения каталога и зарегистрированные пользователи возвращаются к
исходным демо-данным, страница перезагружается. На сервере исходные данные возвращает
пересоздание базы (`docker compose down -v`, затем `docker compose up -d`).

## Что не делается через интерфейс

| Задача | Как сейчас |
|---|---|
| Типы объектов, поля форм, процессы, демо-параметры | Правка `backend/config/object-types.json` и копии `frontend/src/mocks/data/objectTypes.ts` (`docs/data.md`) |
| Нормативы и коэффициенты модели | Правка `backend/config/norms.json` (и `MOCK_CONST` в `frontend/src/mocks/data/model.ts` для автономного демо) |
| Загрузка каталога из файла организатора | Не реализовано |

## Ограничения

- На сервере изменения каталога сразу видны всем пользователям. В автономном демо на моках они
  сохраняются только в браузере администратора.
- Справочники, нормативы и значения по умолчанию (п. 3.1.4 ТЗ) через интерфейс не редактируются.
- Импорта и автоматического обновления каталога нет; версия данных при правке не меняется.
- Источник и дата задаются для робота целиком, а не для каждой характеристики.
