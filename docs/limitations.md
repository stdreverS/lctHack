# Состояние функций, ограничения и план развития

Документ для п. 5.7 ТЗ («какие функции реализованы полностью, частично или представлены
как прототип») и п. 6.9 (ограничения и план). Составлен по коду репозитория.

## Главное

- **Демонстрация работает на моках.** Весь пользовательский путь выполняется во фронтенде:
  запросы к API обслуживает мок-сервер в браузере (`frontend/src/mocks`), данные хранятся в
  `localStorage` браузера. Расчёт подбора и экономики в демо — модель моков (`mock-1.0`).
- **Бэкенд в состоянии каркаса.** `backend/src/Robo.Api` отвечает только на
  `GET /api/v1/robots`, `POST /api/v1/robots` (без сохранения) и `GET /api/v1/robots/{id}`.
  Авторизации, проектов, расчётов и базы данных на сервере нет. Расчётное ядро
  `backend/src/Robo.Core` — заглушка с фиксированным результатом (`econ-0.1-stub`).
- **Данные каталога вымышленные.** 10 роботов в `frontend/src/mocks/data/robots.ts` — условные
  производители и характеристики, ссылки на источники ведут на `example.com`. Датасеты
  организатора (каталог, параметры объектов, `catalog_export_v5`) в проект не загружены.
- **Excel и импорт каталога не реализованы.**

Статусы: **полностью** — работает по ТЗ в демо; **частично** — работает с оговорками;
**прототип** — есть интерфейс или каркас, но не рабочая логика; **нет** — не реализовано.

## План развития

1. **Бэкенд по контракту.** Эндпоинты из `docs/api-examples.md`, EF Core + PostgreSQL, JWT,
   `backend/Dockerfile`, включить `api` и `db` в `docker-compose.yml`.
2. **Расчётное ядро.** Перенести формулы подбора и экономики из моков в `Robo.Core`,
   нормативы — из `backend/config/norms.json`; тесты на совпадение с моками.
3. **Данные организатора.** Импорт каталога CSV/XLSX, демо-наборы трёх объектов, реальные
   источники; версия данных меняется при каждом обновлении каталога.
4. **Экономика по ТЗ.** Замена компонентов в ТСО, амортизация, заёмное
   финансирование (п. 2.1–2.2 дополнений), настраиваемые пороги вывода.
5. **Подбор.** Правила по полям безопасности, зон, санобработки; связь робота с процессом.
6. **Симуляция.** Планы аэропорта и больницы, заторы и объезды, серия прогонов вместо одного.
7. **Выгрузки.** Серверный PDF и Excel.
8. **Интеграции** (п. 3.8.3): импорт объёмов операций из WMS, ставок и цен из ERP/1С.

## Ограничения

- Документ описывает состояние кода на дату составления; статусы проверены по коду и
  ручным прогонам, автоматической проверки соответствия ТЗ нет.
- «Полностью» означает «работает в демо на моках»: для продуктивной эксплуатации нужен
  бэкенд из п. 1 плана.
