# Состояние функций, ограничения и план развития

Документ для п. 5.7 ТЗ («какие функции реализованы полностью, частично или представлены
как прототип») и п. 6.9 (ограничения и план). Составлен по коду репозитория.

## Главное

- **Полная конфигурация работает на сервере.** `docker compose up` поднимает три контейнера:
  `web` (nginx + фронтенд), `api` (ASP.NET Core, `Robo.Api` + `Robo.Core`), `db` (PostgreSQL 17).
  API применяет миграции, заливает демо-каталог и демо-учётки, выдаёт JWT, хранит проекты и
  историю расчётов в БД и изолирует их по владельцу. Все эндпоинты контракта реализованы
  (`docs/api.md`).
- **Расчёт — на сервере**, ядро `Robo.Core`, модель `econ-1.0+rec-1.0`; коэффициенты — в
  `backend/config/norms.json`. Та же модель есть в мок-сервере фронтенда (`mock-1.0`) для
  автономного демо без бэкенда; совпадение ответов проверяют эталонные тесты
  (`docs/economics.md`, «Где считается»).
- **Данные каталога вымышленные.** 10 роботов (`backend/seed/robots.json`) — условные
  производители и характеристики, ссылки на источники ведут на `example.com`. Датасеты
  организатора (каталог, параметры объектов, `catalog_export_v5`) в проект не загружены,
  импорта каталога нет.
- **PDF формируется печатью** из браузера; серверный `report.pdf` отвечает 501. Excel формирует
  сервер.

Статусы: **полностью** — работает по ТЗ на сервере; **частично** — работает с оговорками;
**прототип** — есть интерфейс или каркас, но не рабочая логика; **нет** — не реализовано.
Отсутствие данных организатора учтено в строках 3.3.2 и 3.3.3 и отдельно в статусах других
функций не повторяется.

## План развития

1. **Данные организатора.** Импорт каталога CSV/XLSX в админке и API импорта (п. 3.3.2, 3.8.2),
   демо-наборы трёх объектов, реальные источники; версия данных меняется при каждом
   обновлении каталога.
2. **Экономика по ТЗ.** Замена компонентов в ТСО, амортизация, заёмное
   финансирование (п. 2.1–2.2 дополнений), пороги вывода в интерфейсе.
3. **Подбор.** Правила по полям безопасности, зон, санобработки; связь робота с процессом.
4. **Симуляция.** Планы аэропорта и больницы, заторы и объезды, серия прогонов вместо одного.
5. **Выгрузки.** Серверный PDF.
6. **Проект.** Хранить в проекте сценарии, выбранных роботов, процессы и допущения what-if.
7. **Эксплуатация.** HTTPS, отдельные учётки вместо демо, резервное копирование БД.
8. **Интеграции** (п. 3.8.3): импорт объёмов операций из WMS, ставок и цен из ERP/1С.

## Ограничения

- Документ описывает состояние кода на дату составления; статусы проверены по коду и
  ручным прогонам, автоматической проверки соответствия ТЗ нет.
- Автономное демо на моках (`VITE_USE_MOCKS=true`) повторяет те же функции без сервера; в нём
  данные хранятся в `localStorage` браузера, Excel недоступен.
